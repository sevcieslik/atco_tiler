ATCO Retiler v1.06 operator guide

Before starting a build

Run Validate Setup first. Confirm Central AOI DB, Central Segments, client source GDB, trajectory index, PDAL, EzLAS and Global Mapper show the expected status. Missing Global Mapper blocks ECW only; missing EzLAS blocks zLAS only.

Input mapping

The selected input root should contain aoi, orthos and point_cloud. Products that do not require a source folder can still be run independently.

AOI mismatch / outdated AOI

Do not bypass the error. The selected AOI must match the current central AOI revision and its approved W-drive segment set. Publish/regenerate central AOI/segments first if the production geometry has legitimately changed.

Imagery troubleshooting

TIFF shows white or black background in ArcGIS Pro

Final TIFF should be four-band RGBI with NoData based on the complete 255,255,255,255 condition. Band 4 must remain NIR, not Alpha.

Check ArcGIS Pro at an outside-AOI edge and inspect the four bands. If the TIFF was produced by v1.06, the metadata tag ATCO_BACKGROUND_RULE should describe the unified four-band background rule.

Valid bright pixels look clipped

Retiler protects valid data by changing rare valid per-band 255 values to 254 before setting 255 as NoData. Do not replace this with a simple per-band 255 filter.

ECW is pale / washed out

ECW must be generated from the dedicated QA RGBA intermediate. The intermediate uses RGB from the TIFF and a real Alpha band from its validity mask. NIR must not be used as ECW band 4.

Visible ECW tile seams

Compare the ECW with the TIFF at the same location. If TIFF is clean but ECW shows a seam, check the Global Mapper log and the RGBA intermediate. Also test the actual PLS display because ECW is intended primarily for visual use.

ECW conversion is slow or incomplete

Global Mapper can become unstable with excessive parallel workers. Rerun Missing is preferred after resolving the issue. Review QA\Imagery before deleting valid output.

LiDAR and zLAS troubleshooting

"No input coverage"

The segment did not intersect any source cloud inventory bounds. Confirm the correct point-cloud folder was mapped and inspect source coverage for that entity. Do not fabricate an empty LAZ.

CRS mismatch

Retiler validates the horizontal CRS and preserves a consistent source vertical datum. Mixed or missing CRS headers should be corrected upstream rather than forced through the tool.

Class 7 appears in delivered LAZ

This should not happen. LAZ processing explicitly removes Classification 7. Check the final LAZ, not the source file, and review the LiDAR processing report.

Return Number 0 / Synthetic warning

Retiler reports this condition but does not change it automatically. Review QA\LiDAR\return0_flag_by_class.csv.

Do not apply a blanket ReturnNumber=0 → Synthetic rule. ATCO sample analysis found Return 0 points in Class 93 that require interpretation rather than an automatic flag change.

EzLAS windows appear

v1.06 launches EzLAS hidden and actively hides EzLAS/child windows while conversion is running. If windows still appear, capture a screenshot and note whether it occurs during conversion or verification; the zLAS output itself can still be valid.

zLAS missing / validation failed

Review QA\LiDAR\EzLAS\zlas_validation.csv and the corresponding command/log file. Retiler only accepts a zLAS after EzLAS verification.

Tile Index troubleshooting

Why is Tile Index a shapefile?

This is intentional. Retiler creates an intermediate SHP. The main client GDB will be assembled later with all required products, and this SHP will be imported as TILES.

Why are OBJECTID / Shape_Length / Shape_Area not in the SHP?

They are GDB-managed geometry fields and are created during later import. The SHP contains the business attributes only.

TX fields

BlockNum, ZONE, YEAR, LINE, NAME, fldate, Flightline.

DX fields

PRJ_NAME, YEAR, ZONE. Historic ArcGIS join/licensing fields are deliberately omitted.

Why does a DX filename contain spaces?

DX client-facing names follow the entity naming used in the SoW SQLite. Example: UTIKUMA OILFIELD_0001.

Rerun and Stop

Run Build vs Rerun Missing

Run Build is the deliberate overwrite path for selected products. Rerun Missing is the normal recovery path after an interruption or dependency failure.

Stop

Stop terminates the active processor tree and returns the GUI to Ready. Review QA and output before rerunning; valid completed products may already exist.

Pause / Resume

Pause suspends the processor tree rather than cancelling it. Avoid leaving external applications such as Global Mapper paused for extended periods if the workstation will sleep or disconnect network drives.

Minimum QA checklist before delivery handoff

ProductChecks
TIFFCorrect tile name and extent; four RGBI bands; NIR retained; NoData outside AOI; no black/white edge artefacts; spot-check in ArcGIS Pro.
ECWMatches TIFF spatially and visually; no washed-out colour; no obvious seams in PLS; 3-band RGB visual product.
LAZCorrect extent; Class 7 absent; CRS/vertical datum preserved; classification looks plausible; review Return 0 report rather than auto-editing flags.
zLASEzLAS validation passed; sample opens in ArcGIS Pro; compare against LAZ for extent, point count/classifications and appearance.
Tile IndexOne singlepart polygon per tile; feature count equals approved segments; names correspond to TIFF/LAZ; TX/DX field schema correct; TX trajectory fields populated where matching data exists.
Final principle: central AOI/segments define geometry; Retiler transforms products to that geometry. Unexpected geometry changes should be investigated upstream, not fixed by editing final products.
