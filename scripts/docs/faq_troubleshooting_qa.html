ATCO Retiler v1.08-dev operator guide

Getting started: Validate Input → Eligible Entities → Process

Start with local project data, not a W-drive polygon selection. Map the local input folder containing aoi, orthos and point_cloud as required by the selected products. Select TIFF/ECW/LAZ/zLAS, then click Validate Input directly under the three source indicators in Project Setup. Eligible Entities appears only after successful validation. Choose the eligible entity or entities, then click Process.

Why are AOI, Orthos and Point Cloud grey when the folders exist?

Grey means not yet validated. Merely finding a directory is not evidence of usable geospatial data. The indicators turn green for source types successfully checked during validation. Unselected input types remain grey; an error state and explanation appear when validation fails. Green means that source metadata/footprint checks passed, not that every pixel or point is valid.

Where are the W-drive paths and all the registered Substations?

The central database is a read-only geometry/revision reference, not the operator's file browser. The list shows only circuits or areas matching local Input/AOI and the selected source footprints. Names and revisions are shown, not paths to the original W-drive polygons. An area registered on W: will not appear if the local data do not cover it.

Why is Eligible Entities empty?

Click Validate Input and read the Activity Log. An input AOI must be a valid polygon with CRS. The complete approved circuit AOI must match its current central revision exactly and have a published segment index. For an area, the local AOI must cover at least 99% of its registered current geometry. Selected imagery and/or LiDAR file extents must separately cover at least 99%. Missing extents, mismatched CRS or absent registry entries can exclude candidates.

Does 99% footprint coverage prove there are valid pixels or points?

No. Footprint validation is based on file extents, not the effective image mask or LiDAR density. A polygon can pass spatial preflight while the final TIFF fails for no source coverage due to NoData pixels. Report the case and inspect source files rather than assuming validation guaranteed data everywhere.

What happens when I change Input or products?

The previous eligibility result is invalidated. The indicators return to grey and Process stays disabled until you run Validate Input again. Product dependencies remain: selecting ECW selects TIFF; selecting zLAS selects LAZ.

AOI mismatch / outdated AOI

Do not bypass the error. The local AOI must correspond to the current published revision. Use the existing ATCO AOI Registry publisher to publish a legitimate change (R02 etc.) before processing. Retiler does not edit entities, revisions or source geometry.

Do areas require circuit alignment or Tile Index?

No. Telecoms and Substations are registered as entity_kind=area. They are processed as one polygon, without circuit segment alignment or Tile Index. A missing alignment warning from the registry publisher is not an area processing failure.

Imagery troubleshooting

TIFF shows white or black background in ArcGIS Pro

Final TIFF should be four-band RGBI with explicit NoData=255, restored to enable automatic ArcGIS Pro background masking. Any valid individual 255 values are changed to 254 and background pixels are 255 in all bands. Band 4 remains NIR, not Alpha.

Open a newly rebuilt TIFF in ArcGIS Pro with default raster symbology. The background should be transparent without manual Mask settings. Compare overlap boundaries for white pixels and ensure band 4 remains NIR.

Valid bright pixels look clipped

The ArcGIS Pro-compatible TIFF uses NoData=255; valid input samples equal to 255 are shifted to 254. This is deliberate and must be checked during UAT. If full-coverage uncropped source imagery is available, compare it against the currently loaded source tiles to investigate edge artifacts.

ECW colour, band count or pink background

Current ECW export uses a three-band RGB-only Global Mapper input. The source TIFF keeps four RGBI bands and an internal dataset mask; only TIFF bands 1–3 feed ECW. The ECW intermediate is _GM_RGB3_WHITE.tif, without Alpha or NIR. Masked pixels are filled with white (255,255,255) and Global Mapper exports with BG_TRANSPARENT=NO. Check PLS-CADD and MicroStation Raster Manager as well as Global Mapper. A white ECW background is not transparent.

Visible ECW tile seams or white fringes

Compare against the unchanged TIFF at the same location. Inspect QA\Imagery\gm_rgb_input\*_GM_RGB3_WHITE.tif and the Global Mapper export log. Lossy ECW compression can shift pixels near white-background edges. If a white outline is objectionable in PLS, record a defect; do not treat the white background as equivalent to transparency.

Old pink ECW is still displayed after pulling code

Existing ECWs are retained by Process Missing. Choose Process, select the ECW dependency (TIFF is selected automatically), and confirm overwrite, or use a separate test output location. Check that a new 3-band ECW is being opened and remove stale GIS/PLS raster caches if necessary.

ECW conversion is slow or incomplete

Global Mapper can become unstable with excessive parallel workers. Process Missing is preferred after resolving the issue. Review QA\Imagery before deleting valid output.

Runtime and dependencies

PDAL is missing from the fresh .venv

v1.08 uses a lean project-local scripts\.venv; PDAL is optional for imagery-only work. Selecting LAZ/zLAS causes Validate Input to check LiDAR support and, if necessary, install PDAL automatically into that existing environment. Check Activity Log for Conda download, verification and PDAL installed and validated. If installation fails, review Conda and network access; the base Python does not need reinstalling.

What if Global Mapper or EzLAS is unavailable?

Global Mapper is needed for ECW export, and scripts\tools\EzLAS\EzLAS.exe is needed for zLAS. TIFF-only or LAZ-only processing can proceed without those unrelated tools. Selected products still require the corresponding dependency when processing begins.

Can I process without access to the central AOI database?

No. Current-revision matching requires the read-only database on W:\APPS\PIT\ATCO\database\atco_aoi_master.sqlite. Publishing new revisions is a separate operation using the original registry script.

LiDAR and zLAS troubleshooting

"No input coverage"

A selected approved polygon or segment did not contain usable source LiDAR coverage. Confirm local input\point_cloud and inspect file extents, valid point counts, CRS and polygon matching. The preflight only checks overall file footprints; it cannot guarantee valid points in every selected crop. Do not fabricate empty LAZ.

CRS mismatch

Retiler validates the horizontal CRS and preserves a consistent source vertical datum. Mixed or missing CRS headers should be corrected upstream rather than forced through the tool.

Class 7 appears in delivered LAZ

This should not happen. LAZ processing explicitly removes Classification 7. Check the final LAZ, not the source file, and review the LiDAR processing report.

Return Number 0 / Synthetic warning

Retiler reports this condition but does not change it automatically. Review QA\LiDAR\return0_flag_by_class.csv.

Do not apply a blanket ReturnNumber=0 → Synthetic rule. ATCO sample analysis found Return 0 points in Class 93 that require interpretation rather than an automatic flag change.

EzLAS windows appear

v1.07 launches EzLAS hidden and actively hides EzLAS/child windows while conversion is running. If windows still appear, capture a screenshot and note whether it occurs during conversion or verification; the zLAS output itself can still be valid.

zLAS missing / validation failed

Review QA\LiDAR\EzLAS\zlas_validation.csv and the corresponding command/log file. Retiler only accepts a zLAS after EzLAS verification.

Tile Index troubleshooting (circuits only)

Why is Tile Index a shapefile?

This is intentional. Retiler creates an intermediate SHP. The main client GDB will be assembled later with all required products, and this SHP will be imported as TILES.

Why are OBJECTID / Shape_Length / Shape_Area not in the SHP?

They are GDB-managed geometry fields and are created during later import. The SHP contains the business attributes only.

TX fields

BlockNum, ZONE, YEAR, LINE, NAME, fldate, Flightline.

DX fields

PRJ_NAME, YEAR, ZONE. Historic ArcGIS join/licensing fields are deliberately omitted.

Why does a DX filename contain spaces?

DX client-facing names follow the entity naming used in the SoW SQLite. Example: UTIKUMA OILFIELD_2026_Tiles_v1_0001.

Process, Process Missing and Stop

Choosing products in v1.08

Use Products & Progress. Select All and Deselect All change the product selection; ECW requires TIFF and zLAS requires LAZ. The Process action is disabled until the current inputs/products have been validated and an eligible entity is selected.

Process vs Process Missing

Process is the deliberate overwrite path for selected existing products after confirmation. Process Missing is the normal recovery path after an interruption or dependency failure. Switching products or inputs requires another Validate Input.

Where are the output files?

Each entity has independent folders: TIFF_segments, ECW_segments, LAZ_segments, zLAS_segments for circuits; TIFF_area, ECW_area, LAZ_area, zLAS_area for single-polygon areas. They never overwrite the other geometry type. Old unsuffixed v1.07 output folders are not automatically migrated.

Activity Log

Use the full-width Activity Log page on the left for complete diagnostics, especially excluded entity explanations, Conda installation and processing errors. A smaller collapsible log preview remains on the Process page; choose Show Details / Hide Details there.

Stop

Stop terminates the active processor tree and returns the GUI to Ready. Review QA and output before rerunning; valid completed products may already exist.

Pause / Resume

Pause suspends the processor tree rather than cancelling it. Avoid leaving external applications such as Global Mapper paused for extended periods if the workstation will sleep or disconnect network drives.

Minimum QA checklist before delivery handoff

ProductChecks
TIFFCorrect tile name and extent; four RGBI bands; NIR retained; NoData outside AOI; no black/white edge artefacts; spot-check in ArcGIS Pro.
ECWFreshly rebuilt ECW is RGB-only (no Alpha); outside-AOI background white, no magenta fill; verify PLS-CADD, MicroStation Raster Manager and TerraScan behaviour; inspect tile-edge compression halos and extent against TIFF. A white background is expected, not transparent.
LAZCorrect extent; Class 7 absent; CRS/vertical datum preserved; classification looks plausible; review Return 0 report rather than auto-editing flags.
zLASEzLAS validation passed; sample opens in ArcGIS Pro; compare against LAZ for extent, point count/classifications and appearance.
Tile Index (circuits only)One singlepart polygon per tile; feature count equals approved segments; names correspond to the delivered _2026_Tiles_v1_#### pattern; TX/DX field schema correct; TX trajectory fields populated where matching data exists.
Final principle: local Input drives eligibility; current central registry and approved segments define the permitted geometry. A green input validation indicator is not delivery QA. Unexpected geometry changes should be published upstream, not fixed by editing final products.
